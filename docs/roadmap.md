# Roadmap

Source: spec sections 2, 3, 6.2, 7 (incl. 7.3) and 9 (`docs/spec/gridfinity-generator-spec.de.md`).

## How agents work from this plan

1. Take the first unchecked task whose dependencies are done.
2. Read `AGENTS.md`, then the skills and ADR-digest paragraphs for the area.
3. No code is written until the owner says so (spec section 10). Tasks below describe the work; the owner starts each coding phase.
4. A task is done only when its acceptance criteria are met and the checks that exist at that point pass. Tick it here.
5. Flow (owner, 2 November 2026): Claude Code builds the app with the lids and shows only the lid options. The owner tests. When it is good, Claude Code takes the next feature (Phase C, one feature at a time).
6. A significant decision (new dependency, different approach, a rejected alternative) gets an ADR in `docs/adr/` and a paragraph in `docs/agent/adr-digest.md`.

### One 3MF with plates (owner, 11 November 2026; for the owner to test)

- There is one 3MF, no target per slicer. It is the file of ADR-0008 as before (every piece one object made of components, each part with its colour in a `colorgroup`; the slicer reads the colours and asks which filament each colour gets) plus `Metadata/model_settings.config` with one plate per piece. The plates sit in Bambu Studio's grid (a fifth of the bed between them; the bed is the one typed in the export panel), each piece in the middle of its plate. A split baseplate gets one plate per piece, in one file and in the ZIP of files.
- **Bambu Studio** puts every piece on its own plate and asks about the colours. **OrcaSlicer** loads geometry and colours but not the plates: Orca applies the plates of a file only when it carries project settings (`load_config` in `Plater::priv::load_files`), and a minimal project config would replace the user's printer and process setup by defaults. So in Orca the pieces are arranged by hand (Arrange); the export panel says so. The owner tested five variants with a changed header and object entries in `model_settings.config` (11 November 2026): none made Orca apply the plates, and a header that names OrcaSlicer only changes the warning ("old OrcaSlicer version, loading geometry data only").
- **No `project_settings.config`** on purpose: the two test files of the owner show that the other slicer rejects the profile (Orca into Bambu: colour penetration layers 0 and line widths in percent; Bambu into Orca: raft expansion -1 and relative extruder without `G92 E0`), and it would overwrite the user's own setup. The file does not claim to be from a slicer (`Application Ultimate Gridfinity Generator`).
- Format read from the two saved test files and the open repositories (no code copied, they are AGPL).
