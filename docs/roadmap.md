# Roadmap

Source: spec sections 2, 3, 6.2, 7 (incl. 7.3) and 9 (`docs/spec/gridfinity-generator-spec.de.md`).

## How agents work from this plan

1. Take the first unchecked task whose dependencies are done.
2. Read `AGENTS.md`, then the skills and ADR-digest paragraphs for the area.
3. No code is written until the owner says so (spec section 10). Tasks below describe the work; the owner starts each coding phase.
4. A task is done only when its acceptance criteria are met and the checks that exist at that point pass. Tick it here.
5. Flow (owner, 2 November 2026): Claude Code builds the app with the lids and shows only the lid options. The owner tests. When it is good, Claude Code takes the next feature (Phase C, one feature at a time).
6. A significant decision (new dependency, different approach, a rejected alternative) gets an ADR in `docs/adr/` and a paragraph in `docs/agent/adr-digest.md`.

## Phases

| Phase | Content | State |
|---|---|---|
| A | MakerWorld script (OpenSCAD, Parametric Model Maker) | Done by the owner (outside this repo); serves as oracle |

| C | Bins and baseplates, sliding lid, filler for free space; one feature at a time | In progress: baseplate (C-01 to C-03), bin (C-04 to C-08) and drawer fit with solid filler, split plate and drawer height (C-09 to C-13) built; sliding lid still open |
| D | SolidCraft plugin | Later, only when the plugin system is mature |
| E | Drawer planner, snap connectors for filled plates, text on bin walls, colour by height, bin compartments, scoop, label tab, custom print bed, snap studs instead of magnets | Planned, only after deploy and publication (owner, 4 November 2026) |

Rejected or postponed (spec section 2): desktop app with Tauri or Electron.

## Phase B: web app

- [x] **B-01 Toolchain decision and skeleton.** TypeScript strict, Vitest, Svelte (spec 7.1, owner's choice). Decided (owner, 2 November 2026): Vite with Svelte (template `svelte-ts`, no SvelteKit), Prettier, ESLint, npm; see ADR-0004. Depends on: owner's go for code. *AC:* a build and a test run succeed on an empty project.
- [x] **B-02 Constants module with sources.** One place for all Gridfinity constants (spec section 4), each with its source. *AC:* a test per spec number; the code stops with an error for a dimension that is not defined.
- [x] **B-03 Geometry core.** Manifold WASM in a Web Worker; foot profile 0.8 (45°) / 1.8 vertical / 2.15 (45°), total 4.75; stepped corner radii 3.75 → 1.6 → 0.8. Depends on: B-02. *AC:* foot bottom edge 35.6 for 1x1.
- [x] **B-04 Lid 1x1.** Foot plus plate, dust-protection variant. Depends on: B-03. *AC:* bounding box 41.5 × 41.5 × 7.0 (spec 6.2); plate thickness manual or automatic (total height a multiple of 7; 1u gives 2.25).
- [x] **B-05 Multi-cell lids and foot layout.** `merged` (default, continuous foot, no cross) and `per_cell`; corner magnets only in the four outermost corners of the lid (1x1 has all four corners, 4x4 only the outer four). Depends on: B-04. *AC:* 2x1 bounding box 83.5 × 41.5; closed mesh for 1x1 up to 4x4.
- [x] **B-06 Stackable variant and hollow foot.** Stacking lip `full | corners_only` (corner length parameter), hollow foot `none | open`, corner magnets on the top side of the lid (pocket 6.1 Ø × 2.1, user-changeable), in the four outermost corners only, 2.1 mm deep from the top into the 2.25 mm plate, with at least 0.8 mm of material under the pocket floor (the foot below a solid foot; with a hollow foot the 1.45 mm floor under the plate carries the pocket, 1.6 mm in total under the default pocket, owner, 2 November 2026); no centre magnet and no corner magnets in the foot on lids (owner, 2 November 2026). Depends on: B-05. *AC:* stackable 1x1 with 2.25 plate has height 11.4; the hollow space is one straight cut from below that ends 1.45 mm below the plate (owner, 2 November 2026) and magnet pockets keep 0.8 mm of material under the floor (solid foot; with a hollow foot the 1.45 mm floor under the plate carries the pocket, 1.6 mm in total under the default pocket, owner, 2 November 2026).
- [x] **B-07 Text and symbol.** Text via opentype.js, SVG paths to polygons, then extrusion; modes `none | raised | engraved | flush` per element; offset, rotation, scale. Depends on: B-04. *AC:* all four modes produce closed meshes; fonts bundled with licence checked.
- [x] **B-08 Export.** Binary STL writer; 3MF as one object of separate parts (lid, lip, text, symbol) with `m:colorgroup` colours, see ADR-0008 (first planned as separate objects with base-material colours). Depends on: B-04, B-07. *AC:* parts do not merge into one body; file opens in a slicer (checked in Bambu Studio by the owner: the colour dialog appears and the colours arrive).
- [x] **B-09 Oracle comparison.** Compare the TypeScript output with the reference `.scad` (same parameter names, dimensions, volumes). Depends on: B-06. The reference script is in the repository: `reference/gridfinity_generator.scad`. *AC:* agreed tolerance documented in an ADR; passes for the cases in `skills/reference-oracle/SKILL.md`, compared at or above the spec minimum.
- [x] **B-10 UI and preview.** Svelte UI, three.js preview. Depends on: B-06; design in `docs/design/ui-spec.md` and `brand.md`. *AC:* only the lid options are shown (bin and baseplate stay disabled, labelled "Later"); every lid parameter reachable; values below the spec minimum cannot be entered. (The "not part of the spec" label was dropped by the owner, 2 November 2026.)
- [x] **B-11 Save and load.** Model JSON (type, schema version, parameters, text, colours, SVG as string) in browser storage and as a file; fallback where the save-file picker is missing. Depends on: B-10.
- [x] **B-12 PWA.** HTTPS, manifest, service worker for offline use. Depends on: B-10.
- [x] **B-13 Static hosting.** Dropped (owner, 2 November 2026): hosting is not a task of this repository. `npm run build` makes the static site; see the README for what the server needs. Depends on: B-12.

## Phase C: one feature at a time

Released by the owner on 3 November 2026: the baseplate ("Base"), first; built and merged into `main` the same day.

- [x] **C-01 Baseplate constants and parameters.** Profile 0.7 / 1.8 / 2.15 (wall 4.65), widths 2.85 and 2.15 per side, radii R4 outside and R1.85 / R1.15 inside, with sources, and a test per number. Baseplate parameters with limits (size, style, solid base, corner and centre magnets, ribs). *AC:* a test per spec number; every value below its minimum is rejected.
- [x] **C-02 Baseplate geometry.** Solid and skeleton style, corner magnets in every cell, centre magnet (on a hub with four ribs in the skeleton style), solid base raised automatically under the magnets. Depends on: C-01. *AC:* 1x1 is 42 × 42 × 5.05 with the default base (solid base 0.4); closed mesh for 1x1 up to 4x4 in both styles; a lid 1x1 fits a baseplate cell with about 0.25 mm of gap; pockets keep the 0.4 mm of base under the magnet.
- [x] **C-03 Baseplate in the app.** Part switch enables "Base", parameter groups per `docs/design/ui-spec.md` section 8 (Size with a button that fits the bed, Style, Magnets, Advanced, Colours), preview, bed check, STL and 3MF export, save and load with `type: "baseplate"`. Depends on: C-02. *AC:* lid and baseplate keep their own values while the page is open; a saved baseplate opens again; the lid behaves as before.

Not in this feature: fit to a drawer (own feature, below), bins, sliding lid.

### Bin (released by the owner on 3 November 2026; built and merged into `main` the same day)

Scope (spec 3.2, Open decision 3): width and depth in cells, height in 7 mm units, top edge, walls and floor, magnets and foot. No compartments, no scoop, no label tab. The sliding lid and the filler are their own features. The owner tests after each step that shows in the app.

- [x] **C-04 Bin parameters.** Height 1–12 units, top edge `with_lip | flat_same_height | flat_lower`, wall 1.2–2.5 (below 2.6 with a lip), floor 0.8–5, corner and centre magnets, screw holes, colours; limits and defaults per `docs/design/ui-spec.md` section 8. *AC:* every value below its minimum is rejected, the minimum and the limit are accepted.
- [x] **C-05 Bin geometry.** Per-cell foot, outer body, cavity with the wall and the floor above the foot, stacking lip. Depends on: C-04. *AC (spec 6.2):* 1x1x3 is 41.5 × 41.5 × 25.4 with the lip and 21 without; 2x2 is 83.5 wide; foot bottom edge 35.6; closed mesh from 1x1x1 up to 4x4x6; the cavity wall is the wall setting.
- [x] **C-06 Bin magnets.** Corner pockets in the foot in the four outermost corners, centre magnet in the corner feet, floor raised so 0.8 mm stays above the tallest magnet. No screw holes in bins (owner, 3 November 2026: they only make sense in the baseplate). Depends on: C-05. *AC:* 1x1 has four corner pockets, 4x4 only the outer four; pocket depth and diameter as set.
- [x] **C-07 Bin in the app.** Part switch enables "Bin", parameter groups, preview, bed check, STL and 3MF (body and stacking lip as separate parts when the lip has its own colour), save and load with `type: "bin"`. Depends on: C-05. *AC:* lid, baseplate and bin keep their own values while the page is open.
- [x] **C-08 Hollow foot for the bin.** As on the lid (owner, 3 November 2026): `none | open`, wall 1.2–3, one straight cut from below ending 1.45 mm below the top of the foot; around each magnet pocket a column of the foot stays (pocket plus the wall on each side). Depends on: C-06. *AC:* closed mesh from 1x1 to 4x4 with and without magnets; the cavity ends 1.45 mm below the foot top.

### Filler for the drawer (released by the owner on 3 November 2026, branch `filler-feature`)

Spec 3.2 (decided 2 November 2026): the user gives the width and depth of the drawer; the baseplate is made, and where it is too small for the size, the rest is filled solid ("fit to drawer"). The drawer height that locks the height of bins and lids comes later.

- [x] **C-09 Drawer parameters.** Minimum width and depth in mm (0 = off), where the extra goes −1…1 for each axis; limits and defaults per `docs/design/ui-spec.md` section 8. *AC:* every value outside its limit is rejected; saved baseplates without these values open with the defaults.
- [x] **C-10 Solid filler.** The plate is at least as wide and deep as the drawer; the grid of cells sits where the factor says, the rest stays solid up to the full height, in the solid and the skeleton style. Depends on: C-09. *AC:* a 3x2 plate with a 300 × 250 drawer is 300 × 250 × 5.05; the extra area is solid (volume equals the extra area times the height); at −1 the cells are against the right and the filler on the left, at 1 the other way round, at 0 the cells are centred; closed mesh.
- [x] **C-11 Drawer in the app.** Group "Fit a drawer" in the baseplate panel, a button that sets as many cells as fit the drawer, bed check as before. Depends on: C-10. *AC:* the name and the readout show the plate size; a saved plate opens again.

- [x] **C-12 Split the plate to fit the printer bed (owner, 3 November 2026).** Drawer width and depth up to 1000 mm (up to 24 cells); an option "Split to fit the printer bed" cuts a plate larger than the bed into pieces that each fit it: along the cell boundaries where possible (every cell stays whole), inside the filler where a stretch is longer than the bed; as few pieces as the cell boundaries allow. The preview shows the pieces moved apart; the bed check asks whether the largest piece fits; the export is one file with every piece as its own object, laid out one printer bed apart (a fifth of a bed of gap, like Bambu Studio's plates; in Bambu Studio press Arrange), or one file per piece in a ZIP. Depends on: C-10. *AC:* the pieces together have the volume of the whole plate, each is a closed mesh and fits the bed; a plate that fits is not split; a 3MF has one object and one colour group per piece with unique ids; the ZIP holds one file per piece. Not checked in a slicer by the agent: whether Bambu Studio puts the objects on their own plates by itself (it does not create plates from a plain 3MF, so Arrange is needed).

- [x] **C-13 Drawer height (owner, 3 November 2026).** One drawer height in mm (0 = off, up to 1000), shown in the Size group of the lid and the bin and in "Fit a drawer" of the baseplate. It locks the height of bins and lids: a bin gets at most as many 7 mm units as fit (7 × n + 4.4 with a lip), a lid at most the units or the plate thickness that fit with its lip or raised label; the fields' limits follow and a taller value is lowered. It is saved in the model file. A warning appears when a part is still taller (the drawer is lower than the smallest part). Depends on: C-04, B-04. *AC:* per-rule tests (bin, lid auto and manual, drawer 0 = off); the model file keeps it between 0 and 1000, files without it have 0.

## Phase C, later features

Bins and baseplates in the standard, sliding lid, filler for free space. Bin scope is given by the grid (Open decision 3). Filler: the user enters the width and length of the drawer, the baseplate is generated and, where it is too small, filled solid (fit to drawer, as in the script); later the drawer height is added so that the height of bins and lids stays locked to what fits. The reference script already contains more than Phase B (bin, baseplate, sliding lid, label); the owner accepts that. Extras come once the web app runs, and some may be paid.

## Phase E: after deploy and publication (owner, 4 November 2026)

Planned features. **Do not start them before the owner has deployed and published the app and says so.** One feature at a time, as in phase C; the owner tests each one. Open points are in "Open decisions" 10 to 15; values that depend on test prints (E-04) are the owner's, do not invent them.

- [ ] **E-01 Drawer planner: layout model.** For a baseplate (with the drawer size and height from C-09 to C-13) the user plans which bins and lids sit on which cells: placement on the cell grid, size per bin in cells, no overlaps, height limited by the drawer height. The plan is part of the model file (schema version bump and migration, ADR-0003). Depends on: C-13. *AC:* a plan with bins and lids on a 4x3 baseplate saves, loads and rejects overlaps and parts that do not fit.
- [ ] **E-02 Drawer planner: interface.** Plan view of the plate with the parts on it, add, move and remove a bin or lid, each part uses the parameters of the existing bin and lid panels, list of the planned parts. Design first (`docs/design/ui-spec.md`, mockups by Claude Design). Depends on: E-01. *AC:* the owner can plan a whole drawer without leaving the planner; minimum values and limits as everywhere (spec rule).
- [ ] **E-03 Drawer planner: export.** One 3MF with all planned parts (each part keeps its colours and separate meshes, ADR-0008) or all STLs in one ZIP, one file per part. Depends on: E-01. *AC:* the 3MF opens in a slicer with every part present; the ZIP holds one STL per part and a readable file name per part. How the parts are arranged in the 3MF (as planned in the drawer or laid out on the bed) is open decision 10.
- [ ] **E-04 Snap connectors for filled plates.** Lego-style press studs (round nipples) and sockets in the filled (solid) segments of baseplates that are filled or split (C-10, C-12), so the pieces click together. Tested by the owner (4 November 2026): studs of 3, 5 and 8 mm diameter with a 0.5 mm fillet on top; the matching holes are 3.1, 5.1 and 8.1 mm with a 0.6 mm fillet (hole diameter = stud diameter + 0.1 mm). Stud height and hole depth are not decided yet, and the user can set the clearance afterwards (custom). Depends on: C-12. *AC:* two pieces of a split plate join and hold; the size is a choice of 3, 5 or 8 mm; the clearance parameter changes the fit; height, depth and the limits of the clearance come from the owner.
- [ ] **E-11 Snap studs instead of magnets.** For users without magnets: a stud on the base and a matching hole in the floor of the bin, with the sizes of E-04, in place of the magnet pockets. Depends on: E-04, C-05. *AC:* a bin clicks onto the base; the user chooses between magnets and studs. Position of the studs is decision 12. Owner's idea, 4 November 2026.
- [ ] **E-05 Text on bin walls.** Text stamped (engraved) into the walls of a bin, with the built-in fonts or an uploaded font file, like the lid label (B-07). Depends on: C-05, B-07. *AC:* closed mesh; the engraving depth always leaves material in the wall (wall 1.2 to 2.5, engraving only up to a value below the wall); text size minimum as for the lid label. Which walls, position, depth default and orientation are open decision 11.
- [ ] **E-06 Colour by height.** In the colour settings, a new section of colour bands, with a plus button for another band. The base is the part colour the user has chosen: wherever no band gives a colour, a part keeps it (so the stacking lip has the colour of the whole part unless a band colours it, and a top band without a colour stays in the part colour). The bands are stacked from the bottom of the part over its whole height: each band has a height, the first starts at the bed, the next on top of it, and the top band takes the rest of the part. Example: a 20 mm part with the lowest two bands at 5 mm and the third at 3 mm leaves 7 mm for the top band. A band can be switched to "Lip only" (bins and lids with a stacking lip): it then takes the height of the lip, so the user does not have to guess it. Colour by height replaces the separate lip colour option of the editor (`lip_color_enabled`, `lip_color`), which is removed when this is built; saved models that use it must still open, with the lip colour turned into a "Lip only" band (model file migration, ADR-0003). Depends on: B-08 (3MF colour groups). *AC:* the preview shows the stripes; the 3MF holds every stripe as its own component with its colour (ADR-0008), the stripes join without a gap or overlap; the band heights can never add up to more than the part; a part without bands exports as before; an old model with a lip colour opens with the same look. Open points are decision 13.
- [ ] **E-07 Bin compartments and dividers.** Divide the bin cavity into compartments with walls (dividers) along x and y. Depends on: C-05. *AC:* closed mesh; dividers join the walls and floor; the standard height and the magnet pockets stay as they are. Wall thickness, divider height and how the user sets the compartments are decision 14.
- [ ] **E-08 Bin scoop.** A ramp at the front of a compartment so small parts slide out. Depends on: E-07. *AC:* closed mesh; the scoop never reaches into the walls or the label tab. Size and which compartments get one are decision 14.
- [ ] **E-09 Bin label tab.** A label tab along the front of a compartment for a printed or stuck-on label. Depends on: E-07. *AC:* closed mesh; the tab is printable without support. Size and angle are decision 14.
- [ ] **E-10 Custom print bed.** The user types the width, depth and height of their own printer's bed (any printer, not only the Bambu list), and the bed check, the red band in the preview and the warning read these values and update live as the numbers change; the entered bed is kept in the browser. Depends on: the bed check of the editor (built in phases B and C, task C-12 for the split). *AC:* a part that is too large for the typed bed shows the red band and the warning at once; the buttons that offer a fix use the typed values. What exists (4 November 2026): a square custom bed with rounded corners and a build height. Whether the bed may be rectangular and whether a keep-free corner can be entered is decision 15.

## Open decisions (spec section 9)

1. ~~Placeholder values~~ Decided (2 November 2026): hollow-foot wall 1.2, skin 0.8, corner lip length 10, emboss depth 0.6, sliding-lid clearance 0.3, centre magnet 5.0 × 2.0 with clearance 0.2 are the defaults (spec section 4).
2. ~~Manual plate thickness~~ Decided: default and minimum from the spec, the user can only increase it. Rule: the spec value is always the minimum and the default; smaller is not allowed.
3. ~~Bin scope~~ Decided (2 November 2026): given by the grid: width and depth in cells, height in 7 mm units, plus the script's options (lip style, foot, magnets, walls and floor). No compartments, scoop or label tab.
4. ~~Filler variant~~ Decided (2 November 2026): fit to drawer as in the reference script (drawer width and length, the rest filled solid). Later: drawer height locks the height of bins and lids. Extended bins and half-cell pockets are not planned.
5. ~~Centre magnet and hollow foot~~ Decided (2 November 2026): the centre magnet goes only into feet (bins) and the baseplate, not into lids; lids have corner magnets on the top side. In the baseplate the centre magnet sits on a hub with four ribs (`center_ribs`); in the bin foot there are no ribs, only a 1.2 mm rim that holds the magnet.
6. ~~UI font~~ Decided for now (2 November 2026): Inter for text, IBM Plex Mono for numbers, until the owner says otherwise. IBM Plex Sans (SemiBold) stays only an option for the lid text in the script. The shortlist in spec 7.3 is parked.
7. ~~The project's own licence~~ Decided (2 November 2026): CC BY-NC-SA 4.0. Open: whether it covers the files the app outputs, contributions by others, and when a `LICENSE` file is added (ask the owner first). See `skills/licences-and-credits/SKILL.md`.
8. ~~Which spec is the yardstick~~ Decided: the reference drawings in `reference/gridfinity-reference-drawings/` and the official documentation.
9. ~~Prompt for the web app~~ Written (2 November 2026); code released for Phase B.
10. **Drawer planner export (E-03).** Is the 3MF the drawer as planned (all parts in place) or the parts laid out on the bed for printing? Does the plan include the baseplate? Owner decides.
11. **Text on bin walls (E-05).** Which walls (all four, front only, per wall), position and orientation, engraving depth default and limit, shared text settings with the lid label. Owner decides.
12. **Snap connector values (E-04, E-11).** Tested (4 November 2026): stud 3, 5 and 8 mm with a 0.5 mm top fillet, hole 3.1, 5.1 and 8.1 mm with a 0.6 mm fillet. Open: stud height, hole depth, default and limits of the clearance, how many studs per segment and where, and where the studs sit on the base and in the bin floor (E-11). Owner decides; no value is invented.
13. **Colour by height (E-06).** Decided (4 November 2026): the base is the user's part colour; bands are stacked from the bottom over the whole height, each with its own height, the top band takes the rest; a band without a colour (also the top one) keeps the part colour; the lip has the part colour unless a band colours it; a "Lip only" switch sets a band to the lip height; the separate lip colour option goes away. Open: how many bands at most, whether band edges snap to the layer height of the printer, and whether bands apply to every part of a model or per part (plate, text). STL has no colours and stays one file. Owner decides.
14. **Bin interior (E-07 to E-09).** How compartments are entered (a count per axis with equal split, or free divider positions), minimum and default divider thickness and height, scoop size and which compartments get one, label tab size and angle. Owner decides; no value is invented.
15. **Custom print bed (E-10).** Rectangular or square only, whether a keep-free corner can be entered, and whether it also fixes the build height. Owner decides.
