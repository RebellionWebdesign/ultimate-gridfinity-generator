# ADR-0009: Sets (one baseplate with several bins)

- **Status:** Accepted (the owner's answers of 15 November 2026; he released the work the same day)
- **Source:** user feedback passed on by the owner

## Context

The editor keeps one baseplate, one bin, one label, one connector and one lid, each with its own values and its own `modelId`. A bin is not tied to a baseplate. Saved models are a flat list in `localStorage` (`ugg.models`, at most 12), one entry per part with the host's id for a label or a connector. Renaming a bin keeps its `modelId`, so it replaces the stored bin; there is no way to keep a second bin. A user who fills a baseplate needs several bins that belong together.

## Decision

- **A set is its own record:** `setId`, a name, one baseplate (with its connector), and a list of bins. Each bin has its own `id`, name, bin values, label, and its place on the plate. Old single-part models stay readable (schema version bump and migration, ADR-0003).
- **Place:** the user types a row and a column in the assembly tab, counted on the grid seen from above, and may turn a bin by 90 degrees. There is no dragging; interactive layout belongs to the owner's other app.
- **Plate check:** every bin is checked against the plate while it is designed: it must lie inside the grid and must not overlap another bin. "Full is full": when no free place is left, no further bin is added and a warning says so (like the bed check: red numbers, a short alert, red text on the download button). The plate never grows.
- **Label and lid:** each belongs to its bin and takes its size from the bin (the label does this now; the lid follows, owner, 15 November 2026). A bin may have no lid.
- **Assembly view:** Baseplate and bins stand together as on a plate, with their labels and lids in place (as in Bambu Studio or Orca). The 3D view cannot be edited; the places of the bins (column, row, turn) are set in the assembly tab beside it, everything else about a bin in its own tab.
- **Export:** the user chooses when exporting (owner, 15 November 2026): **as a set**, one 3MF with the baseplate and every bin, label and lid as its own object (ADR-0008 for each part), or **loose**, every part as a file of its own in a ZIP, as the parts are exported one by one today. STL always gives a ZIP with one file per part; "as a set" then adds the placement as a `read-me.txt`.
- **Saving:** a set is one entry, saved only after the consent for browser storage (privacy statement unchanged). There is no fixed number of bins or sets: the room in `localStorage` decides (owner, 15 November 2026). The old limit of 12 entries (`MAX_STORED`) goes away for sets; when the browser refuses to store, the editor says so as it does now ("Not saved in this browser").

## Rejected

- Loosely linked bins, each with only a plate id: a set could not be saved or exported as a whole.
- A free interactive layout in this app: it is the drawer planner, which the owner builds elsewhere.

## Consequences

The store, the model file format and the storage list change; the schema version goes up. The geometry of the parts does not change. The plate check and the placement are new pure functions that can be tested without the browser.
