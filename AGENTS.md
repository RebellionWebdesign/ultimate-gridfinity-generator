# Ultimate Gridfinity Generator: instructions for agents

A browser app (PWA) that generates Gridfinity parts (lids first; bins and baseplates later, feature by feature) and exports STL and 3MF. All geometry is computed in the user's browser. This file is a router: the hard rules, then the skill to read for your task. Humans: README.md.

The full planning record is `docs/spec/gridfinity-generator-spec.de.md` (German, the source of truth for requirements and numbers). Everything else in `docs/` is derived from it and written in English.

## Start here
Work: `docs/roadmap.md` (take the first unchecked task whose dependencies are done). Decisions already taken: `docs/adr/`, with the rules a change must keep in `docs/agent/adr-digest.md`. Open questions: "Open decisions" in the roadmap. Phase E (drawer planner, snap connectors for filled plates, text on bin walls, colour by height, bin compartments and scoop and label tab, custom print bed, snap studs instead of magnets) is planned for after deploy and publication, and phases F to H (desktop app, MakerWorld script rebuilt from the app, tool inserts from a photo) are far-future ideas; do not start any of them before the owner says so. When something is not settled by the spec, the ADRs or the code, ask the owner; do not guess.

## Hard rules
- **No code until the owner says so.** Until then, only Markdown. The owner announces when code gets written (spec section 10). **Released on 2 November 2026: Phase B (web app, lids only).** Bins, baseplates and every later feature stay Markdown-only until the owner releases them.
- **The Gridfinity standard is the law.** All dimensions run on the Gridfinity system, base 7 (height) and 42 (grid). Constants live in one place with a source for each (`skills/gridfinity-spec/SKILL.md`). Tests check every spec number. If you need a dimension that is not in the spec, stop and report it; never invent a value.
- **Sources: official only.** Original repositories, releases, documentation and guides. No aggregator or secondary pages. If a source is unreachable, say so; do not fill the gap from memory.
- **Facts and options, not orders.** The owner decides. Do not silently change a spec number; report the deviation.
- **Compute in the browser.** No server-side geometry, no server storage for STL/3MF files (ADR-0002).
- **One geometry kernel: Manifold WASM, in a Web Worker** (ADR-0001). Do not add another kernel without a new ADR.
- **Parts of a model stay separate parts** (plate, lip, text, symbol) in 3MF, as components of one object with their own colours (ADR-0003, ADR-0008), so the slicer can assign filaments; never merge them into one body.
- **Language.** Chat with the owner in German; code, identifiers and repository files in English.
- **Licences and credits.** No new dependency without asking the owner first. Keep the Gridfinity copyright and licence notice where the spec demands it. Dependencies go against an allow-list; GPL, LGPL and AGPL code is not allowed in the bundle unless the owner decides otherwise in an ADR (`skills/licences-and-credits/SKILL.md`).
- **The reference `.scad` is the test oracle.** Parameter names, dimensions and volumes are compared against it (`skills/reference-oracle/SKILL.md`). Geometry therefore exists twice (OpenSCAD and TypeScript); that is a deliberate cost.
- **Fonts are self-hosted.** No Google Fonts CDN or other external font loading (spec 7.3, `skills/licences-and-credits/SKILL.md`).
- **Public repository.** Never add credentials, personal data or private network details. Ask the owner before adding third-party material (other people's files, screenshots, images, fonts).
- **Show your work.** Run the checks that exist before you report a task done. Report what you checked and what failed, not only what passed.

- **Git: atomic commits, owner approves first.** Agents may commit and push, but only after the owner has seen and approved the change. One logical change per commit (one task or one fix, nothing mixed). Before every commit and every push, show the owner `git status`, the diff summary and the proposed commit message, then wait for approval. Never force-push, never rewrite published history. Commit messages are short, factual and imperative, in English. No advertising, no tool or model attribution, no `Co-Authored-By` or "generated by" lines, no links to sessions, in commits, pull requests and files.
